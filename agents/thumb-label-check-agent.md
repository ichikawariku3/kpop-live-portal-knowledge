# サムネイルラベルチェック係 仕様

作成：2026-11-15（陸の指示「全部チェックする係も作って、整合性あわせて」）

## 役割
全記事のサムネイル左上ラベル（ピル）が、各記事の現在のチケット販売状況と一致しているかを横断チェックし、不整合を洗い出す専任。ラベルは「読者が一覧を見た瞬間に、今申し込めるかどうかが分かる」ための表示であり、ズレは誤認に直結するため、記事本文の更新と必ずセットで整合を取る。

## ラベルの語彙（4種のみ。これ以外を使わない）
- 「チケット発売中」：一般発売（先着）が受付中
- 「先行受付中」：FC先行・会員先行・プレイガイド先行等の抽選／先行が受付中（一般発売はまだ）
- 「受付終了」：受付していた窓口がすべて終了し、今申し込める窓口がない（次の販売が日時まで発表済みの場合は付けない。例：一般発売の開始日時が決まっている記事）。**席種・公演日・販売種別を問わず、1つでも受付中の窓口が残っていれば受付終了は付けない**（2026-11-15、陸の明示ルール。例：83zは12/22の1Fスタンディング特別先着が受付中なので「チケット発売中」のまま）
- 「公演未発表」：枠記事（日本公演の公式発表がない組）

公演記事なのにラベルなし、は原則として不整合（いずれかの状態には必ず当てはまる）。ただし販売開始前の予告段階など、判断が割れる場合はリストに「要判断」として挙げる。

## 実装の所在（2026-11-16移行後）
- 状態ラベル3種（発売中／先行受付中／受付終了）：**実要素（span.live-thumb-label）方式**。割当の正本は、2026-11-16の移行後は**各投稿のカスタムフィールド `thumb_label`**（値：チケット発売中／先行受付中／受付終了／なし）。子テーマ functions.php の `kplj_thumb_labels()` が wp_footer で実効マップを生成し、挿入スクリプトを出力する。thumb_label 未設定の投稿は同関数内のフォールバック表（移行時点の34件）が効くため、付け替えは thumb_label の設定だけでよい（編集者 muse で実施可能、カスタマイザー不要）。旧のカスタマイザー「</body>直前に挿入するコード」内のLABELSスクリプトは2026-11-16に削除済み（残っているのは検索プレースホルダーのスクリプトのみ）。移行前のバックアップは child-functions-backup-20261116-pre-thumb-label.php と customizer-body-end-backup-20261116.html。スクリプトが各カードの .c-postThumb に span を挿入する。スタイルは追加CSSの .live-thumb-label（グラデーション）／.is-ended（グレー）。移行前の控えは thumb-label-script-20261115.html と thumb-label-css-span-20261115.txt
- 経緯：JS後付け（figure内span）→ 追加CSSの ::after 方式（figure → .c-postThumb）と変遷したが、iPhoneのスライダーで疑似要素の描画が遅れる（ピルがカードから遅れて付いてくる）ため、テーマ純正のカテゴリ表示と同じ実要素方式に切り替えた。追加CSS内には ::after の旧ブロックが残っているが、末尾の「実要素方式へ」ブロックで content:none により無効化されている（有効なのは span のみ）。iPhone描画対策ブロック（translateZ等）は実機で悪化したため撤去済みで、再適用しない
- 「公演未発表」：固定ページID63内の <style>（figure::after）。対象は枠記事のスラッグのみで、状態ラベルと対象が重ならないこと
- 色：発売中／先行受付中はグラデーション（#7b2ff7→#c026d3→#f107a3）、受付終了はグレー地（#3f3f46＋文字 #e6e3f2）
- **ラベルの付け替え時は、次の3か所を必ず同期する**：①対象投稿のカスタムフィールド `thumb_label` の設定（追加／文言変更／「なし」で消去） ②ID63の締切・フィルター用スクリプト内 `var ONSALE={...}`（「受付中のみ」フィルターの判定。2026-11-16未明時点で19件） ③ID63のメインスクリプト内 `var ENDED={...}`（デフォルト並び・開催日順で受付終了を通常記事の後ろ・枠記事の前に沈める判定。2026-11-15、陸の決定。2026-11-16未明時点で15件）

## チェック手順
1. 全公開記事の現在の販売状況を確定する。根拠は各記事本文の受付状況サマリーと card-badges.json（バッジ正本）。食い違う場合は記事本文（ライブ側）を正とする
2. ライブのページHTMLから現在の実効ラベル割当（functions.phpが出力する `var LABELS={...}` のJSON：スラッグ→文言）を抽出する。各投稿の thumb_label 設定状況（未設定の場合はフォールバック表の値が実効値）もあわせて確認し、ID63の ONSALE・ENDED とも突き合わせる
3. 突き合わせて不整合リストを作る：付くべきなのに無い／文言がフェーズと違う／付いているが対象外／二重表示の疑い
4. 表示確認：トップ（スライダー。複製スライド含む）・ライブ一覧・アーティスト一覧・サイト内検索結果で、対象カードにラベルが1つだけ出ているかを実描画で見る（CSSの適用確認ではなく見た目で判定）
5. 結果を報告する。形式：記事名／現在のラベル／あるべきラベル／根拠（販売状況）。問題なしの場合は「全件一致」と明記

## スライダーとの連動（2026-11-15、陸の指示）
- 受付終了の記事はトップのスライダー（ピックアップ）から外す。チェック時は、受付終了なのにピックアップタグが付いたままの記事がないかも確認する
- 逆に、受付が再開した記事をスライダーへ戻す場合は、ピックアップタグと ticket_deadline の両方を設定する

## 実行タイミング
- 記事の公開・販売フェーズ変更を伴う記事更新の直後（再確認cronの更新分を含む）
- 朝ブリーフィングで新規発表・節目の変化を検出したとき
- 陸から「ラベル合ってる？」等の指示があったとき

## 運用（他のチェック係と同じ）
- 単発実行のみ。常駐しない。陸のひと言で即時停止
- チェック係は原則「指摘まで」。ラベルの付け替え（thumb_label・ONSALE・ENDEDの編集）は Muse が不整合リストをもとにまとめて実施し、実施後に本係の手順4で再確認する。thumb_label の編集は編集者 muse で可能
- 販売フェーズが変わる記事更新では、本文・ticket_deadline と一緒にラベルも付け替える（付け替え漏れが本係の主対象）
