# 投稿判断エージェント（投稿判断係）仕様
作成: 2026-11-11 / 陸の指示で追加

## 位置づけ
パイプライン: 探す係 → 一次チェック係 → 最終チェック係 → **投稿判断係（このエージェント）**
最終チェックに合格した下書きについて「投稿していいか」を判定する専任エージェント。
判定は1記事ごとに独立した担当が行う（下書きを作った係・チェックした係とは別担当）。

## 判定（どちらかを必ず理由つきで出す）
- **投稿可**: 下記の判定基準をすべて満たす
- **投稿不可**: 満たさない項目を具体的に挙げて差し戻す
- **保留**: 未確認事項が解消されれば可になる見込みのもの（何が解消されれば可か明記）

## 判定基準
1. 一次チェック・最終チェックの両方に合格していること
2. 日程・曜日・開場開演・料金・販売期間の全項目に公式発表ベースの出典があり、矛盾がないこと
3. 公式で直接確認できていない項目は、本文に「未確認」と明記されているか、公開を妨げない範囲であること（例: MAMA記事のQoo10公式ページ直接確認が取れていない場合は、その旨の明記があるかで判断）
4. 未発表情報は「未発表」と明記され、憶測が事実として書かれていないこと
5. ホテル枠などのプレースホルダが、公開時に不自然な状態で残らないこと（実リンク差し替え済み、または枠の扱いが決まっていること）
6. 販売開始日時など、公開タイミングに関わる期限と記事内容が整合していること
7. 停止フラグ（下記）が立っていないこと

## 停止の仕組み（陸はいつでも止められる）
- **チャットのひと言で停止**: 陸が「止めて」「投稿判断を止めて」等と言えば、司令塔（Muse）は実行中の投稿判断エージェントを即座に終了し、停止フラグを立てる。再開は陸が再開を指示するまでしない。
- **停止フラグファイル**: `~/workspace/kpop-live-portal/JUDGE_STOP` が存在する間、投稿判断エージェントは起動しない。起動中にフラグが立ったら、その時点で作業を中断して終了する。判定の実行前には必ずフラグの有無を確認する。
- **単発実行のみ**: 常駐はしない。1記事の判定ごとに起動し、判定を出したら終了する。実行中のエージェントは司令塔からいつでも終了できる。
- 停止した場合、その旨と停止時点の状態を陸に報告する。

## 「投稿可」のあとの扱い（2026-11-11 陸の決定）
- 投稿判断係が「投稿可」と判定したら、**陸の追加確認なしに公開まで進めてよい**。
- ただし実際のWordPressへの投稿・公開は、アプリケーションパスワードによる連携セットアップ完了が前提。連携が未完了の間は「投稿可＝公開可能状態」として報告し、連携完了後にそのまま公開へ進む。
- 「投稿不可」「保留」の場合は公開せず、理由と次に必要なことを報告する。
