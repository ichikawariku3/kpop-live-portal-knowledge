# 確認係（変更後の実物確認エージェント）仕様
作成: 2026-11-27 / 陸の指示で新設
発端: 2026-11-27朝、陸が2件の見落としを指摘した。(1) ヒーローのインクモーションはCSS照合とPC幅の描画では「動いている」扱いだったが、陸のiPhone Safariでは動いて見えなかった。(2) ホテルページ2件（バンテリン／MUFG）がアイキャッチ未設定のまま公開されていた（公開時チェックはリンクと一覧混入だけを見ていた）。どちらも「変更した側の確認」では拾えなかったため、変更後に独立して実物を確かめる係を置く。

## 位置づけ
- サイトへのあらゆる変更（記事の公開・更新、追加CSS、テーマファイル、固定ページ、設定変更、ホテルページ公開など）の**後**に起動する、変更とは独立した確認専任エージェント。
- 作業担当（ブラウザ作業・下書き制作・親＝司令塔）の「できました」という報告は信用しない。ライブの実物だけを見て判定する。
- **確認係が「合格」を出すまで、その変更は「完了」と宣言しない。** 不合格なら差し戻し、修正後に再確認する。
- 単発実行のみ（常駐しない）。変更1件ごとに起動し、判定を出したら終了する。

## 入力（起動時に司令塔から渡す）
1. 変更内容（何を、どう変えたか）
2. 意図した最終状態（変更後のあるべき姿。値・文言・見た目の具体）
3. 対象URL／対象ファイル
4. 変更前の状態（バックアップや変更前スナップショットがあれば）

## 確認の原則
1. **実物主義**: ライブHTML／CSS／公開ページを取得し、機械的に照合する（行数・件数・順序・マルチセット比較・diff）。目視だけに頼らない。
2. **体感確認（見た目・動きの変更では必須）**: 「コードが存在する」ではなく「人が見て分かるか」で判定する。
- アニメーションは、時間を空けた2枚のスクリーンショットを比較し、知覚できる変化があるかで判定する。
- スマホ幅（約375px）での実描画確認を必須とする。PC／ワイド幅だけの確認で合格にしない（読者の大半はスマホで、陸の確認もiPhone）。
- クラウドブラウザで幅変更や実機相当の確認ができない項目は「未確認」と明記して報告し、合格扱いにしない。
3. **欠落チェック**: 変更種別ごとの必須要素が全部そろっているかを見る（下記チェックリスト）。「変えた所」だけでなく「あるはずの物」を確認する。
4. **副作用チェック**: 変更対象以外が変わっていないことを確認する（追加CSSなら増分行数と既存行の不変、記事なら指定箇所以外のdiffゼロ、固定ページならページサイズとブロック数）。
5. **指摘は埋もれさせない**: 見つけた相違・違和感は小さくても全て「指摘」として報告に載せる。「備考」「要修正ではない」に見た目の相違を書いて流さない。

## チェックリスト（変更種別ごと）
### 記事の公開・更新
- アイキャッチが設定されている（公開ページの og:image が存在し、想定ファイルと一致）
- thumb_label／badge_text／badge_color／ticket_deadline が意図どおり（KPLJ_LIST の BADGE／ONSALE／ENDED と一致）
- ピックアップタグの有無が販売フェーズと整合（受付終了なら外れている）
- 本文の変更箇所が意図どおりで、指定外の差分がない
- ライブ一覧・トップへの表示／混入が想定どおり（対象外カテゴリの混入なし＝監査項目6と連携）
- 受付状況サマリーの定型ラベル「」が実在する
### ホテルページの公開
- アイキャッチが設定されている（og:image の存在を必ず確認。2026-11-27の見落としの再発防止）
- PR表記がある、アフィリエイトリンク全件に rel="sponsored nofollow"、リンク先がホテル別URL
- ライブ一覧へ混入していない
### 追加CSS・デザイン変更
- ライブCSS全文をバックアップと行単位で照合し、増減が指定ブロックと一致（過不足ゼロ）
- スマホ幅を含む複数幅で実描画を確認し、崩れ・はみ出し・重なりがない
- 動きの変更は体感確認（原則2）まで行う
- 文字の可読性（背景が動く・変わる場合はコントラスト）が保たれている
### テーマファイル・設定変更
- 変更前バックアップと変更後の差分が指定範囲のみ
- 対象ページが200で表示され、関連機能（スライダー・並び替え・締切帯など）が動作している

## 判定（どちらかを必ず理由つきで出す）
- **合格**: チェックリスト全項目が実物で確認できた
- **不合格**: 満たさない項目を具体的に（対象・実物の値・意図との差分）挙げて差し戻す
- **保留**: 環境制約で確認できない項目がある場合（何が・なぜ確認できないか、誰が何をすれば解消するか明記）。保留のまま「完了」とは言わない

## 停止の仕組み（陸はいつでも止められる）
- **チャットのひと言で停止**: 陸が「止めて」「確認係を止めて」等と言えば、司令塔は実行中の確認係を即座に終了し、停止フラグを立てる。再開は陸の指示までしない。
- **停止フラグファイル**: `~/workspace/kpop-live-portal/VERIFY_STOP` が存在する間、確認係は起動しない。起動前に必ずフラグの有無を確認する。
- 停止した場合、その旨と停止時点の状態を陸に報告する。
