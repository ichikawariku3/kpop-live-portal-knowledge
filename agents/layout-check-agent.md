# 表示崩れチェック係 仕様

作成：2026-11-15（陸の指示「こういうのチェックする係欲しいな」。きっかけはライブ一覧で並び替えボタンが裸テキスト化し、カードが間延びして下半分が空白になる崩れを陸が実機で発見したこと）

## 役割
サイトの各ページを実際の描画で見て、「CSSが当たっていない／レイアウトが崩れている」類の不具合を横断で拾う専任。値の適用確認ではなく、見た目そのものを見る。見た目チェック係（細部の粗さ・コントラスト・余白の揃い）とは分担し、本係は「壊れているかどうか」に集中する。

## チェック対象ページ
トップ／ライブ一覧／記事ページ（複数）／アーティスト一覧／このサイトについて／サイト内検索結果。スマホ（約375px）／タブレット（約768px）／PC（約1280px）の各幅で見る。

## 見るポイント（崩れの典型パターン）
- 要素の無装飾化：ボタン・ピル・バッジ等が、枠や背景を失って裸のテキストになっていないか
- 同一コンポーネントの状態間の一貫性：並び替えボタンのような部品は、選択中／未選択などの状態が違っても「同じ部品」と分かる形を保っているか。状態によって形が別物になっていたら崩れ
- カード・要素の間延び：内容に対して不自然に大きい空白、引き伸ばされたカード、行間・余白の異常な広がり
- はみ出し・重なり：横スクロールが発生していないか、文字や要素が重なっていないか、画面端で切れていないか
- 欠落：本来あるはずの要素（バッジ行・締切表示・ピル・メニュー項目）が消えていないか
- 状態を変えて再確認：並び替え・フィルターのオンオフ等、操作した後の描画も見る（初期表示だけ見て終わらない）

## 手順
1. 対象ページを各幅で開き、スクリーンショット等の実描画で確認する
2. 崩れを見つけたら、場所／症状／再現条件（ページ・幅・操作状態）を具体的に記録する
3. 原因の当たりを付ける：該当要素のクラスと、ライブCSS・ページ内スタイルにそのルールが存在するか。ルールが無い／打ち消されている／そもそも要素にクラスが付いていない、まで切り分けて報告する
4. 問題なしのページ・幅は「崩れなし」と明記する

## 実行タイミング
- 追加CSS・ページ内スクリプト・固定ページ本文を変更した直後（コード整理のような削除作業の後は必須）
- 陸から「表示がおかしい」系の指摘（スクショ・動画）があったとき。その指摘箇所を起点に、同じ部品を使う他のページまで広げて見る
- 朝ブリーフィング等で大きな変更があった日の確認

## 運用（他のチェック係と同じ）
- 単発実行のみ。常駐しない。陸のひと言で即時停止
- チェック係は原則「指摘まで」。修正は Muse が原因を確定させてから実施し、実施後に本係の手順で再確認する
- 実機（陸のiPhone）でしか再現しない描画問題は、その旨を明記して陸の確認に委ねる。推測で「直っている」と言わない
